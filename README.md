# 学校予定共有ボード (School Schedule Board)

Google Apps Script (GAS) と Google スプレッドシートを活用した、小中高校・特別支援学校向けの軽量・高信頼な予定・タスク共有ボードです。

---

## 1. アプリ概要

一般的なカレンダーとは異なり、**「学校で現在何が動いているか（今日・今週・今月・年間）」**を一目で把握するための共有ボードです。

### 主な特徴
- **シンプルな1画面構成**: 「今日」「今週」「今月」「年間」「＋追加」の直感的な操作体系
- **安心の変更履歴管理**: 予定の修正・追記・状態変更のすべてを「誰が・いつ・何をしたか（変更前・変更後）」として自動記録
- **追記と修正の明確な分離**: 既存の本文を壊さずに進捗メモを積み重ねられる「追記」機能
- **誤削除の防止**: 完全削除機能を持たず、「完了」「中止」「取消」として履歴を残しつつ落ち着いたトーンで表示
- **スマートフォン最適化**: 画面幅320pxの最小端末でも横スクロールなしで快適操作、44px以上の押しやすいタップ領域
- **学校現場専用用語**: IT専門用語（スプリント、バックログ等）を一切排除し、誰でも迷わず利用可能
- **高信頼性・並行性**: Google Apps Script の `LockService` による二重登録防止・連番採番・トランザクション保証

## 3. Google Sheets 構成

本システムは Google スプレッドシート内の以下の3つのシートを使用します。シートが存在しない場合は自動作成されます。

### 3.1 `Tasks` シート (予定データ)
| 列 | 列名 | 内容 | 例 |
| :--- | :--- | :--- | :--- |
| A | `taskId` | 連番ID | `TASK-20261003-0001` |
| B | `title` | 予定タイトル | `学芸会プログラム印刷` |
| C | `description` | 予定の内容・詳細 (複数行可) | `印刷室の輪転機で500部印刷` |
| D | `periodType` | 予定時期区分 | `今日`, `今週`, `今月`, `日付指定`, `年間`, `未定` |
| E | `specifiedDate`| 日付指定時の日付 (YYYY-MM-DD) | `2026-10-15` |
| F | `status` | 進行状態 | `検討中`, `進行中`, `保留`, `完了`, `中止`, `取消` |
| G | `assignee` | 担当教職員名 | `教務主任` |
| H | `createdBy` | 登録教職員名 | `教頭` |
| I | `createdAt` | 登録日時 (YYYY/MM/DD HH:mm) | `2026/10/03 09:00` |
| J | `updatedBy` | 最終更新教職員名 | `校長` |
| K | `updatedAt` | 最終更新日時 (YYYY/MM/DD HH:mm) | `2026/10/03 14:30` |

### 3.2 `History` シート (変更履歴ログ)
| 列 | 列名 | 内容 | 例 |
| :--- | :--- | :--- | :--- |
| A | `historyId` | 履歴固有ID | `HIST-xxxx-xxxx-...` |
| B | `taskId` | 対象のタスクID | `TASK-20261003-0001` |
| C | `timestamp` | 操作日時 (YYYY/MM/DD HH:mm) | `2026/10/03 14:30` |
| D | `actor` | 操作教職員名 | `校長` |
| E | `actionType` | 操作種別 | `新規登録`, `修正`, `追記`, `状態変更` |
| F | `fieldName` | 変更項目 | `全体`, `タイトル`, `詳細`, `期間`, `指定日`, `状態`, `担当者`, `追記` |
| G | `beforeValue` | 変更前の値 | `学芸会プログラム印刷` |
| H | `afterValue` | 変更後の値 | `学芸会プログラム印刷 (カラー表紙)` |
| I | `comment` | 備考・追記本文 | `状態を「検討中」から「進行中」に変更` |

### 3.3 `Members` シート (教職員マスター)
| 列 | 列名 | 内容 | 例 |
| :--- | :--- | :--- | :--- |
| A | `memberId` | メンバーID | `MEM-0001` |
| B | `name` | 氏名・役職名 | `校長` |
| C | `active` | 有効フラグ | `TRUE` |
| D | `sortOrder` | 並び順数値 | `1` |

## 4. 初期設定方法 (非エンジニア向けステップ解説)

### ステップ1: 新規スプレッドシートの作成
1. Google ドライブを開き、「新規」>「Google スプレッドシート」をクリックします。
2. スプレッドシートのタイトルを「`学校予定共有ボード`」などに変更します。

### ステップ2: Apps Script エディタの起動
1. スプレッドシート上部メニューの「拡張機能」>「Apps Script」をクリックします。
2. プロジェクト名を「`学校予定共有ボード`」に変更します。

### ステップ3: スクリプトファイルの配置
1. 左側のファイル一覧にある `コード.gs` の内容を消去し、リポジトリの `src/Code.js` の内容をコピー＆ペーストして保存します（ファイル名を `Code` に変更）。
2. 「ファイルを追加（＋）」>「スクリプト」を選択し、ファイル名を `Logic` と入力して、`src/Logic.js` の内容をコピー＆ペーストして保存します。
3. 「ファイルを追加（＋）」>「HTML」を選択し、ファイル名を `index` と入力して、`src/index.html` の内容をコピー＆ペーストして保存します。

### ステップ4: 初期データの作成 (ワンクリック実行)
1. Apps Script エディタ上部の関数選択プルダウンから `initSheets` を選択します。
2. 「実行」ボタンをクリックします。
3. 初回実行時、Google による権限確認ウィンドウ（「アクセスを承認」）が表示された場合は、画面の案内に従ってアクセスを許可してください。
4. 実行が完了すると、スプレッドシートに `Tasks`, `History`, `Members` の3つのシートと初期メンバーが自動生成されます。

## 5. デプロイ方法 (Webアプリとして公開)

1. Apps Script エディタの右上にある青い「**デプロイ**」ボタン >「**新しいデプロイ**」をクリックします。
2. 左上の歯車アイコン（種類の選択）をクリックし、「**ウェブアプリ**」を選択します。
3. 各項目を以下のように設定します：
   - **説明**: `学校予定共有ボード v1.0`
   - **次のユーザーとして実行**: `自分` (推奨: スプレッドシートのオーナー権限で安全に一括読み書きされます)
   - **アクセスできるユーザー**: `全員` (組織内運用の場合は「所属組織の全員」を選択)
4. 「**デプロイ**」をクリックします。
5. 表示された「**ウェブアプリの URL**」をコピーします。
6. このURLを学校内の教職員（PCのお気に入りや職員室連絡用チャット、校内掲示等）に共有して完了です。ログインなしで直接利用できます。

## 6. Members (教職員) 追加・変更方法

1. スプレッドシートの「`Members`」シートを開きます。
2. 新しい行に以下の形式で追加します：
   - A列 (`memberId`): `MEM-0007` (ユニークなID)
   - B列 (`name`): `1年主任` や `山田先生` などの表示名
   - C列 (`active`): `TRUE` (休職・異動時は `FALSE` に変更すると選択肢から自動非表示になります)
   - D列 (`sortOrder`): プルダウンでの並び順 (例: `7`)
3. アプリを再読み込みすると、登録・更新時のプルダウン一覧に即座に反映されます。

## 7. 利用方法

### 7.1 画面上部のタブ切り替え
- **今日**: 今日の予定（「今日」指定または指定日が本日のもの）
- **今週**: 今週の予定（月曜日〜日曜日）
- **今月**: 今月の予定（1日〜末日）
- **年間**: 年間すべての予定（未定や先々の予定も含む全体把握用）

### 7.2 新しい予定の追加
1. 画面右上の緑色「**＋ 新しい予定を追加**」ボタンを押します。
2. タイトル、予定時期、詳細内容、担当者、あなたの氏名（登録者）を選択・入力します。
3. 「**登録する**」を押します。二重連打防止機構が働くため安全に登録されます。
   *(※一度選択したあなたの名前はブラウザに自動記憶され、次回から自動選択されます)*

### 7.3 予定の修正
- 内容や担当者、時期を変更したいカードの「**修正**」ボタンを押します。変更差分はすべて自動で履歴に保存されます。

### 7.4 追記メモの追加
- 「**追記**」ボタンを押すと、元の文章を書き換えることなく進捗連絡や資材到着などのメモを追加できます。カード上にもタイムスタンプ付きで即時表示されます。

### 7.5 状態変更
- 「**状態変更**」ボタンから「保留」「完了」「中止」「取消」などを選択して保存します。
- 完了や中止になった予定は一覧から消滅せず、落ち着いた灰色表示（淡色表示）になり、過去の記録として確実に残ります。

### 7.6 変更履歴の確認
- 「**履歴**」ボタンを押すと、過去のすべての操作（誰が・いつ・何をどう変更したか）がタイムライン形式で時系列表示されます。

## 8. 注意事項

- **完全削除機能について**: 本システムには誤操作によるデータ消失を防ぐため、完全削除ボタンはありません。誤って登録した場合は状態を「**取消**」に、取りやめになった場合は「**中止**」にしてください。
- **タイムゾーン**: すべての日時計算は日本標準時 (`Asia/Tokyo`) を基準としています。
- **ブラウザ環境**: スマートフォン（iOS Safari, Android Chrome）、タブレット、PC（Chrome, Edge, Safari）の最新ブラウザに対応しています。

## 9. テスト方法

本プロジェクトには完全なオフラインテストハーネスが付属しています。GAS環境にデプロイする前にローカルで全ロジック・API・シナリオの検証が可能です。

### 前提条件
- Node.js (v18以上推奨)

### 全テストの一括実行
```bash
node test/run-all-tests.js
```

### 個別テストスイートの実行
```bash
# 1. 期間判定ロジック・境界値テスト (月曜/日曜/月末/年末年始/うるう年)
node test/test-logic.js

# 2. バックエンドAPI・排他ロック・連番採番・二重登録防止テスト
node test/test-backend.js

# 3. Level 3 統合テスト、Level 4 人間テストケース1〜10、第58項最終シナリオ、履歴完全性、UXテスト
node test/test-human-scenarios.js

# 4. UI構造・DOM・CSSレスポンシブ・アクセシビリティ検証
node test/test-ui-dom.js
```
